Relevant walletlib, JSON-RPC, auth-repository, Local MWA, Android accessibility, and HTTP logging was reviewed separately. This included the normal signing, injected rejection, report/share, and direct-send periods, rather than only app start/restart logs.

- **No credential or sensitive payload value found:** zero PEM markers, seed/mnemonic/recovery-phrase hits, association-token hits, raw-payload-field hits, 90+ base58 runs, or long transaction/message/payload/signature assignments. No raw private key, authorization token, association token, keystore/key password, release-signing secret, or raw sensitive transaction/message bytes appeared in the inspected window.
- Eight `MobileWalletAdapterSession` verbose lines printed encoded **received public ECDH handshake keys** (155–156 decimal digits), four wallet/client pairs. The paired messages identify them as received public keys, with nearby `generateSessionECDHKeyPair` method names, WebSocket message sizes and encrypted-session lifecycle events. These are public protocol metadata, not private key output. The scanner's generic long opaque-string rule matched these eight public values; it did not justify classifying them as secrets.
- `AuthRepositoryImpl` verbose messages mentioned “auth token” but printed `AuthRecord` metadata (identity, public account key bytes, Devnet chain, scope, issue/expiry times), **not the raw token**. The four `Returning AuthRecord from auth token:` suffixes begin `AuthRecord{id=...`; no token value follows that phrase. This is unusually verbose dependency metadata and should not be copied into public evidence as raw logs.
- Other broad `password`/`credential` matches were Android system/component names and `AccessibilityNodeInfoDumper` `password` properties (including `password=false`), not password values. JSON-RPC dependency logging showed connect/disconnect, message-received, response IDs and the public `-3` protocol error, without serialized bodies. Walletlib WebSocket logging showed message sizes and lifecycle. Public addresses, method names, protocol error names, bounded hashes, timing, and transaction signatures were treated as public metadata.
